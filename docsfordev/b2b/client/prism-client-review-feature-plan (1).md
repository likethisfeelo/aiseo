# PRISM 클라이언트 검토 스티커 기능 기획서

## 1. 기능 목적

프로젝트 일정표, 시안, 콘텐츠 문서 등을 클라이언트 전용 웹페이지로 전달하고, 클라이언트가 확인이 필요한 위치에 스티커를 붙이듯 의견을 남길 수 있게 한다.

이 기능은 결재나 최종 승인 시스템이 아니다. 회의 전에 의견을 수집하고, 회의에서 함께 이야기할 항목을 빠르게 정리하기 위한 커뮤니케이션 도구다.

핵심 흐름은 다음과 같다.

> 전용 링크 접속 → 비밀번호 입력 → 이름 입력 → 문서 확인 → 스티커 붙이기 → 어드민에서 요청 확인 → 회의 및 작업에 활용

---

## 2. 사용자 구분

### 클라이언트

- 전용 링크와 비밀번호로 접속한다.
- 최초 접속 시 본인 이름을 입력한다.
- 문서의 특정 항목에 요청 스티커를 붙인다.
- 자신과 다른 클라이언트가 남긴 스티커를 확인할 수 있다.
- 필요한 경우 본인이 붙인 스티커를 삭제한다.

### 어드민

- 클라이언트가 남긴 요청을 한 화면에서 확인한다.
- 요청 유형, 작성자, 문서 위치, 작성 시각을 확인한다.
- 내부 작업이 끝난 항목에 `확인 완료` 체크를 한다.
- 어드민의 체크 상태는 내부 작업 관리용이며 클라이언트에게 표시하거나 재전송하지 않는다.

---

## 3. 접속 방식

### 클라이언트 전용 링크

프로젝트별로 별도의 링크를 제공한다.

예시:

`review.example.com/stork`

### 접속 순서

1. 프로젝트 비밀번호 입력
2. 비밀번호가 맞으면 이름 입력
3. 이름을 저장한 뒤 검토 문서 진입
4. 동일 기기에서는 일정 기간 이름 입력 생략 가능

복잡한 회원가입이나 이메일 인증은 사용하지 않는다.

---

## 4. 클라이언트 화면

### 기본 구성

- 상단: 프로젝트명, 현재 작성자 이름, 효과음 켜기/끄기
- 중앙: 검토할 일정표 또는 콘텐츠 문서
- 우측 패널: 현재 문서에 등록된 스티커 목록
- 모바일: 우측 패널 대신 하단에서 올라오는 요청 목록 사용

본문은 일반 문서처럼 편하게 읽을 수 있어야 한다. 요청 기능이 문서보다 더 강하게 보이지 않도록, 평소에는 각 항목 옆에 작은 `+` 버튼만 표시한다.

## 5. 스티커 종류

모든 스티커는 PRISM의 정사면체와 빛의 굴절을 공통 모티프로 사용한다. 홀로그램 질감, 검은색 타이포그래피, 흰색 다이컷 테두리를 적용한다.

### 설명 요청

- 톱니형 원형 실루엣
- 큰 물음표가 중심 그래픽
- 표시 문구: `설명 요청`
- 용도: 의미, 범위, 진행 방식 등에 대한 추가 설명 요청

### 조정 또는 확인 필요

- 원형 실루엣
- 순환 화살표와 프리즘 그래픽
- 표시 문구: `조정 또는 확인 필요`
- 용도: 내용 수정, 표현 조정, 자료 확인 등이 필요한 경우

### 날짜 변경

- 정사면체 형태의 삼각형 실루엣
- 표시 문구: `날짜 변경`
- 용도: 현재 기재된 일정의 변경을 요청하는 경우
- 희망 날짜가 있으면 선택적으로 메모 가능
- 희망 날짜가 없으면 별도 입력 없이 스티커만 붙일 수 있음

날짜 변경 입력 예시:

- `희망 날짜가 있나요?`
- `없음, 회의에서 협의`
- `있음` 선택 시 날짜 또는 짧은 메모 입력

### 협의 필요

- 별 모양과 말풍선을 결합한 실루엣
- `협의 필요!` 문구를 가장 강하게 강조
- 용도: 문서상 답변보다 회의에서 함께 이야기하는 것이 적절한 경우

제작된 SVG 파일:

- `01-explanation-request.svg`
- `02-adjust-or-check.svg`
- `03-date-change.svg`
- `04-discussion-needed.svg`

## 6. 스티커 등록 흐름

1. 클라이언트가 문서 항목 옆의 `+` 버튼을 누른다.
2. 네 종류의 PRISM 스티커가 팝업으로 펼쳐진다.
3. 원하는 스티커를 선택한다.
4. 선택적으로 짧은 메모를 작성한다.
5. 날짜 변경 스티커일 때만 희망 날짜 입력 여부를 선택할 수 있다.
6. 등록 직전에 선택 위치를 다시 확인한다.

위치 확인 문구 예시:

> `7월 3일까지 최종 검수` 부분에  
> `날짜 변경` 요청을 남기시는 게 맞습니까?

버튼:

- `아니요`
- `네, 붙일게요`

7. 등록되면 해당 항목에 스티커가 나타나고 우측 요청 목록에도 추가된다.

## 7. 붙이기 애니메이션과 효과음

스티커를 붙일 때는 짧고 경쾌한 피드백을 제공한다.

### 붙이기 애니메이션

- 스티커가 화면 중앙 또는 선택 메뉴에서 해당 위치로 빠르게 이동
- 크기 `70% → 112% → 100%`
- 약간의 회전 후 제자리 정착
- 홀로그램 빛이 한 번 가로질러 지나감
- 주변에 작은 프리즘 조각 또는 별빛 입자가 3~5개 나타났다가 사라짐
- 전체 애니메이션 길이: 약 `350~500ms`

### 붙이기 효과음

- 밝고 짧은 `뿅`, `팝`, `플링` 계열
- 유리 프리즘을 살짝 튕기는 듯한 맑은 고음 추가
- 길이: 약 `150~300ms`
- 음량은 일반 알림음보다 작게 설정

추천 인상:

> `pop + tiny crystal chime`

효과음은 사용자가 버튼을 누른 직후 재생하므로 브라우저 자동재생 제한에 영향을 받지 않는다.

---

## 8. 스티커 삭제 UX

### 삭제 버튼 표시

- 평소에는 삭제 버튼을 숨긴다.
- 스티커 위에 마우스를 올리면 우측 상단에 작은 `×` 버튼이 나타난다.
- `×`는 검은색 원 안의 흰색 문자 또는 흰색 원 안의 검은색 문자로 표시한다.
- 스티커의 문구를 가리지 않도록 외곽선 위에 걸쳐 배치한다.
- 본인이 작성한 스티커에만 삭제 버튼을 표시한다.

모바일에서는 마우스 오버가 없으므로:

- 스티커를 한 번 누르면 `수정 · 삭제` 메뉴 표시
- 메뉴 바깥을 누르면 닫힘

### 삭제 동작

- 사용자가 `×`를 누르면 별도의 확인창 없이 즉시 삭제한다.
- 실수에 대비해 화면 아래에 약 4초 동안 실행 취소 메시지를 표시한다.

예시:

> 스티커를 삭제했습니다. `되돌리기`

### 삭제 애니메이션

- 스티커가 살짝 눌린 뒤 축소
- 프리즘 조각처럼 3~4개로 흩어지거나 빛으로 사라짐
- 전체 길이: 약 `250~400ms`

### 삭제 효과음

- 붙이기보다 낮고 짧은 `퐁`, `슉`, `톡` 계열
- 불쾌한 오류음이나 휴지통 소리는 사용하지 않음
- 길이: 약 `120~250ms`

추천 인상:

> `soft pluck + reverse sparkle`

---

## 9. 효과음 설정

- 상단에 작은 스피커 아이콘 제공
- 기본값은 켜짐
- 클릭하면 전체 스티커 효과음을 끌 수 있음
- 설정은 해당 브라우저에 저장
- 시스템의 `동작 줄이기` 설정이 켜진 경우 애니메이션을 최소화
- 소리가 꺼져도 시각적 피드백은 유지

효과음 파일은 가벼운 `WebM/OGG + MP3` 조합으로 제공하는 것이 좋다.

예시 파일:

- `sticker-pop.mp3`
- `sticker-remove.mp3`

---

## 10. 요청 목록

클라이언트 화면의 요청 목록에는 다음 정보를 표시한다.

- 스티커 아이콘
- 요청 유형
- 요청이 붙은 문서 항목
- 작성 메모
- 날짜 변경 시 희망 날짜
- 작성자 이름
- 작성 시각

목록의 요청을 누르면 문서의 해당 위치로 이동하고, 스티커가 짧게 반짝인다.

필터:

- 전체
- 설명 요청
- 조정 또는 확인 필요
- 날짜 변경
- 협의 필요

---

## 11. 어드민 화면

어드민에서는 프로젝트별로 클라이언트 요청을 표 또는 목록 형태로 모아본다.

표시 정보:

| 내부 체크 | 요청 유형 | 요청 위치 | 메모 | 희망 날짜 | 작성자 | 작성 시각 |
|---|---|---|---|---|---|---|
| □ | 날짜 변경 | 최종 검수 | 내부 검토 시간 필요 | 7월 10일 | 김수진 | 6월 18일 |
| ☑ | 설명 요청 | 일일 피드백 | 전달 방법 문의 | - | 이현우 | 6월 18일 |

### 어드민 확인 완료 체크

- 어드민이 내부 작업을 마친 항목에 체크한다.
- 체크된 항목은 어드민 목록에서 흐리게 표시한다.
- `미확인`, `확인 완료` 필터를 제공한다.
- 체크는 언제든 다시 해제할 수 있다.
- 이 상태는 클라이언트 화면에 노출하지 않는다.
- 체크 시 클라이언트에게 메시지나 알림을 발송하지 않는다.

어드민 체크는 승인, 결재, 답변 완료를 의미하지 않는다. 오직 내부 작업 진행 여부를 구분하기 위한 표시다.

## 12. 상태 및 데이터 항목

스티커 한 건에 필요한 기본 정보:

- 프로젝트 ID
- 문서 ID
- 문서 항목 ID
- 요청 유형
- 메모
- 희망 날짜 또는 날짜 메모
- 작성자 이름
- 작성자 식별값
- 작성 시각
- 어드민 내부 확인 여부
- 삭제 여부

문서의 표시 문구 자체를 위치값으로 사용하지 않는다. 문구가 수정되어도 요청 연결이 유지되도록 각 일정과 문단에 고유한 항목 ID를 부여한다.

## 13. 권한 원칙

- 프로젝트 비밀번호를 통과한 사용자만 문서를 볼 수 있다.
- 클라이언트는 본인이 작성한 스티커만 삭제할 수 있다.
- 어드민은 전체 스티커를 확인하고 정리할 수 있다.
- 어드민의 내부 체크 상태는 클라이언트 API 응답에서 제외한다.
- 링크와 비밀번호가 외부에 노출될 경우를 대비해 프로젝트 비밀번호를 변경할 수 있어야 한다.

---

## 14. 1차 개발 범위

1. 프로젝트별 전용 링크와 비밀번호
2. 클라이언트 이름 입력
3. 문서 항목별 스티커 등록
4. 등록 위치 재확인
5. 날짜 변경 시 선택적 희망 날짜 입력
6. 스티커 및 요청 목록 표시
7. 마우스 오버 `×` 즉시 삭제
8. 삭제 실행 취소
9. 붙이기·삭제 애니메이션과 효과음
10. 효과음 켜기·끄기
11. 어드민 요청 목록
12. 어드민 내부 확인 완료 체크와 필터

---

## 15. 추후 확장 기능

1차 버전에서는 제외하되 필요 시 추가할 수 있다.

- 스티커 메모 수정
- 이메일 또는 메신저 알림
- 회의용 요청 출력 및 PDF 저장
- 문장 일부를 드래그해 정확한 텍스트에 요청 연결
- 프로젝트별 효과음 또는 스티커 테마 변경
- 요청 통계와 회의 기록

---

## 16. 최종 UX 원칙

- 결재 시스템처럼 무겁게 만들지 않는다.
- 클라이언트는 읽다가 `+`를 누르고 스티커만 붙이면 된다.
- 메모와 희망 날짜는 모두 선택 사항이다.
- 요청이 붙은 정확한 위치를 등록 전에 한 번 확인한다.
- 스티커는 재미있고 브랜드답지만 문서의 가독성을 방해하지 않는다.
- 붙이기와 삭제는 빠르고 경쾌하게 반응한다.
- 어드민 체크는 철저히 내부 관리용으로 분리한다.
