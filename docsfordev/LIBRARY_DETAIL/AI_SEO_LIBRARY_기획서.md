# AI SEO LIBRARY — 게이트형 라이브러리 리더 기획서

> daydream 라이브러리 UX를 차용한, "표지(카테고리) → 챕터(포스트)" 구조의 콘텐츠 리더.
> 본문 20% 미리보기 후 회원가입/로그인 게이트로 리드를 확보한다.

---

## 1. 목적과 한 줄 정의

- **목적**: 라이브러리 콘텐츠를 미리보기로 노출해 검색·SNS 유입을 받고, "더보기" 지점에서 **무료 회원가입**으로 전환시켜 리드 DB를 쌓는다.
- **한 줄 정의**: *표지로 묶고, 20%로 낚고, 가입으로 잠근다.*

---

## 2. 핵심 컨셉

| 개념 | 설명 |
|---|---|
| 표지(Cover) | 카테고리 역할. 여러 포스트를 담는 묶음. 책 표지처럼 라이브러리에서 노출 |
| 챕터(Chapter) | 표지 안에 든 포스트. 표지 내에서 **순서(order)** 를 가짐 |
| 다대다(N:N) | 하나의 포스트가 **여러 표지**에 동시에 들어갈 수 있음. 표지마다 순서는 별도 |
| 미리보기 게이트 | 본문 앞부분(약 4 스크롤 분량)만 노출, 하단 **더보기 버튼** → 클릭 시 **가입 팝업(모달)** → 가입/로그인 시 해제 |
| 이어보기 | 가입/로그인 직후 페이지 이동 없이 **그 자리에서** 나머지 본문 즉시 노출 |

## 3. 데이터 모델

### 3-1. 엔티티

**Cover (표지/카테고리)**
```
id            string  (slug)
title         string
description   string
thumbnail     url
tag           enum    (Playbooks | Case Studies | ...)
is_published  bool
created_at    datetime
```

**Post (포스트/챕터)**
```
id            string  (slug)
title         string
tag           enum
author        string
published_at  datetime
read_minutes  int
lead          text    ← 미리보기로 항상 노출되는 도입부
body          html    ← 게이트 대상 본문
seo_meta      json    (og, description, canonical)
is_published  bool
```

**CoverPost (매핑 = N:N + 순서)**
```
cover_id      fk
post_id       fk
sort_order    int     ← 표지 내 챕터 순서
PK (cover_id, post_id)
```

### 3-2. 관계 요약
- `Cover 1 ── N CoverPost N ── 1 Post`
- 같은 `post_id`가 여러 `cover_id`에 존재 가능 → **중복 배치**
- 표지별 순서는 `CoverPost.sort_order`로 독립 관리 (드래그 정렬)

## 4. 화면 구성 (IA)

```
[라이브러리]  ── 이미 구축됨 (표지 캐러셀)
     │ Read Post / Related Post 클릭
     ▼
[리더 페이지] /library/{cover}/{post}
 ├─ 상단 네비 (처음엔 우측에 떠있음 → 스크롤다운 시 탑바로 도킹)
 │   · AI SEO LIBRARY / 기업서비스 / 강의 / 로그인 / 상담문의
 ├─ 히어로 (Back · 태그 · 제목 · 저자/일자 · 읽기시간)
 ├─ 좌: 표지 카드 + 챕터 목록(순서, 중복배치 표시)
 ├─ 우: 본문 카드
 │     ├─ lead (항상 노출)
 │     ├─ body 미리보기 (약 4 스크롤 분량, 하단 페이드)
 │     └─ ▼ [더보기 버튼] → 가입 팝업(모달)        ←── 비회원
 │     └─ body 100%                                ←── 회원
 └─ 하단: ★ 메인 라이브러리 섹션 그대로 노출
         (책등 캐러셀 + 펼쳐진 표지 + 탭/검색 + 전체보기)
```

### 4-1. 상단 네비 도킹 동작 (★ 추가)
- **초기 상태(스크롤 최상단)**: 메인 페이지와 동일하게 좌측 브랜드는 숨고, 우측 메뉴 묶음만 **떠 있는 캡슐 그룹**으로 노출. 바 배경/구분선 없음.
- **스크롤다운 시(약 40px 이상)**: 네비에 `docked` 상태 부여 → 전체 폭 **탑바**로 전환(블러 배경 + 하단 보더 등장), 좌측 브랜드 페이드인, 우측 캡슐 배경은 평평하게.
- 구현: `scroll` 이벤트로 `nav.docked` 클래스 토글(`DOCK_AT` 임계값). CSS 트랜지션으로 부드럽게 전환.

### 4-2. 하단 메인 라이브러리 섹션 (★ 변경)
- 기존 "이 표지의 다른 글 · 추천" 카드 그리드를 제거하고, **메인 라이브러리 섹션을 그대로** 하단에 노출.
- 구성: 카테고리 탭(전체/Case Studies/Playbooks) + 검색 + **가로 스크롤 책등(spine) 캐러셀** + 좌우 화살표 + 전체 보기 버튼.
- 현재 읽는 글은 책등 사이에서 **펼쳐진 흰색 표지 카드**로 강조(메인의 "펼친 책" 연출). 다른 책등 클릭 시 해당 포스트로 전환되고 좌측 사이드바·게이트가 다시 적용됨.

- **URL 설계**: `/library/{cover-slug}/{post-slug}`
  - 한 포스트가 여러 표지에 있을 때 표지별 URL이 생기므로 **canonical**을 대표 표지 1개로 지정 (중복 콘텐츠 방지)

## 5. 미리보기 게이트 로직

### 5-1. 노출 깊이 (★ 변경)
- 항상 노출: `lead` 전체
- 미리보기 본문: 화면을 **약 4번 스크롤한 지점**까지 노출 (1920×1080 기준)
- 구현: 본문 미리보기 높이 = `뷰포트 높이 × PEEK_VH_MULT` (기본 `2.4` ≈ 뷰포트 2.4배 ≈ 약 4 스크롤)
  - `PEEK_VH_MULT` 상수 하나로 노출 깊이 조절 (값↑ = 더 많이 보여줌)
  - 마스킹 영역 하단에 그라데이션 페이드 → 자연스럽게 "더 있다"는 신호
- 본문이 미리보기 높이보다 짧으면 게이트 미적용(전체 노출), 더보기 버튼도 숨김
- (참고) "정확히 20%" 같은 비율 고정이 아니라 **스크롤 깊이 기준**으로 변경됨. 비율 기준이 필요하면 `min(비율, 스크롤높이)`로 병행 가능

### 5-2. 더보기 버튼 → 가입 팝업
- 미리보기 끝에 중앙 정렬된 **더보기 ▾** 버튼 (페이드 위에 떠 있음)
- 클릭 시 펼쳐지는 대신 **회원가입 팝업(모달)** 오픈
  - 모달 구성: 이메일·비밀번호 + 가입 버튼 / 소셜(카카오·구글) / 로그인 토글 / 닫기(X·배경클릭·ESC)
  - 로그인 토글 시 같은 모달이 로그인 모드로 전환
- 가입/로그인 성공 → 모달 닫힘 → 게이트 해제

### 5-3. 상태 전이
```
비회원 ─[더보기 클릭]─▶ 가입 팝업 ─[가입]─▶ 회원 ─▶ 본문 100% + 같은 위치 유지
비회원 ─[더보기 클릭]─▶ 가입 팝업 ─[로그인 토글→제출]─▶ 회원 ─▶ 해제
회원   ─[새 포스트 진입]─▶ 게이트 없이 바로 100%
```

### 5-4. 이어보기 UX
- 해제 시 페이지 리로드 금지. DOM에서 마스크/더보기존만 제거.
- 팝업 오픈 직전 스크롤 위치를 저장 → 해제 후 동일 위치로 복원 (점프 방지).

## 6. 인증 연동 (현재 로그인 시스템과 결합)

> 현재 로그인 부분이 이미 구축되어 있으므로, 더보기 버튼이 띄우는 **가입 팝업(모달)** 에서 기존 인증 API만 호출한다.

- **회원가입**: `POST /auth/signup {email, password}` → 성공 시 **자동 로그인(토큰 발급)** → 게이트 해제
- **로그인**: `POST /auth/login {email, password}` → 토큰 저장 → 게이트 해제
- **세션 유지**: 토큰을 쿠키/스토리지에 저장, 재방문 시 회원이면 게이트 미노출
- **소셜 로그인(선택)**: 카카오/구글 버튼을 가입 팝업에 추가하면 전환율↑ (기존 소셜 연동 재사용) — 목업에 이미 반영됨
- **리다이렉트 불필요**: 같은 페이지에서 처리해 "이어보기" 경험 유지. 별도 로그인 페이지로 보냈다면 `?next=현재URL&anchor=스크롤` 로 복귀.

## 7. 관리자(어드민) 요구사항

| 기능 | 내용 |
|---|---|
| 표지 관리 | 생성/수정/발행, 썸네일, 태그, 라이브러리 노출 순서 |
| 포스트 관리 | lead / body 분리 에디터, SEO 메타, 읽기시간 |
| 챕터 배치 | 표지에 포스트 추가/제거, **드래그로 순서 변경** |
| 중복 배치 | 한 포스트를 여러 표지에 연결 (체크박스 멀티 셀렉트) |
| canonical 지정 | 다중 표지일 때 대표 표지 1개 선택 |
| 게이트 설정 | 노출 깊이(기본 약 4 스크롤 = `PEEK_VH_MULT` 2.4), 표지/포스트별 on·off |

## 8. SEO 고려사항 (★ pSEO 사업 특성상 중요)

- **클로킹 금지**: 검색봇에게만 전체를 보여주고 사용자에게 숨기면 패널티. 권장 방식 두 가지:
  1. **lead + 본문 20%를 실제 HTML로 노출**(봇·유저 동일) → 색인은 미리보기 기준. 가장 안전.
  2. 구글의 **Flexible Sampling(`isAccessibleForFree` + `paywalledContent` 구조화 데이터)** 적용 → 페이월 콘텐츠를 합법적으로 색인. (전체 색인이 필요할 때만)
- **canonical**: 다중 표지 URL은 대표 1개로 통일.
- **구조화 데이터**: `Article` + (페이월 시) `isAccessibleForFree:false`, `hasPart` 마크업.
- **LLM 인용**: lead와 첫 헤딩을 질문-답변형으로 작성하면 미리보기 영역만으로도 LLM 인용 확보.

## 10. 개발 단계 (마일스톤)

1. **M1 — 데이터/어드민**: Cover·Post·CoverPost CRUD, 드래그 정렬, 중복 배치
2. **M2 — 리더 페이지**: 좌 챕터 사이드바 + 우 본문, lead/body 분리 렌더
3. **M3 — 게이트**: 스크롤 깊이 기반 미리보기 + 더보기 버튼 + 가입 팝업(모달) + 이어보기
4. **M4 — 인증 결합**: 기존 시스템 연동, 세션 유지, 소셜 로그인(선택)
5. **M5 — SEO**: canonical, 구조화 데이터, Flexible Sampling 결정
6. **M6 — 측정**: 미리보기→가입 전환율, 표지별 유입, 가입 후 열람 깊이 대시보드

## 11. 성공 지표 (KPI)

- 미리보기 도달 → **가입 전환율** (1차 핵심)
- 가입 후 **본문 완독률 / 챕터 추가 열람 수**
- 표지(카테고리)별 유입·전환 비교
- 검색/LLM 유입 중 미리보기 영역만으로 인용된 비율
